# My Driving God DB - 後端資料庫結構

## 1. 核心設計理念

本系統後端基於 Django ORM 建立，旨在打造一個數據驅動的車隊安全管理平台。

整體架構圍繞三大核心實體：**人員 (User)**、**群組 (Group)**、與**行程 (Trip)**。透過記錄每一趟行程中由 AI 視覺偵測到的駕駛行為，系統能進行評分並提供改善建議，最終提升整體行車安全。

---

## 2. 資料模型架構

### 2.1 主要實體 (Core Entities)

-   **User / PersonnelProfile (人員)**
    -   系統中的基本使用者單位。`PersonnelProfile` 額外擴充了駕駛員所需的資訊，例如駕照類型、駕駛年資等。

-   **Group (群組 / 車隊)**
    -   組織與管理「人員」的單位，例如「台北車隊A組」。管理員可在此發布公告或邀請成員。

-   **Trip (行程)**
    -   系統的**核心記錄單位**，代表一趟完整的駕駛過程。它串連了**「是誰 (User)」、「在哪個車隊 (Group)」、「用了哪台設備 (Device)」**，並記錄了該趟行程的開始與結束時間。

### 2.2 關鍵紀錄與數據 (Key Records & Data)

-   **AiVisionLog (AI 視覺事件紀錄)**
    -   記錄行程中發生的**具體危險駕駛事件**。例如：在 `2025-10-12 14:30:15` 偵測到「重度疲勞」。這是所有評分的基礎來源。

-   **ScoringStandard (評分標準)**
    -   定義了各種危險駕駛事件的扣分標準。例如：「重度疲勞」扣 5 分。

-   **VideoRecord (影像紀錄)**
    -   儲存與特定「行程」相關的影像片段 URL，用於事後調閱與佐證。

### 2.3 系統與管理功能 (System & Management)

-   **邀請與啟用碼 (Invitation & Activation Codes)**
    -   `ActivationCode` 用於新用戶註冊；`InvitationCode` 則讓管理員能邀請成員快速加入特定群組。

-   **公告系統 (Announcements)**
    -   分為「系統公告」(全體可見) 與「群組公告」(僅群組成員可見)，方便資訊佈達。
